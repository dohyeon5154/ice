기존 방식한계
육안 예찰작업자 숙련도에 따라 판정 편차가 크고, 초기 병반(직경 2~5mm) 인지가 어렵다. 기록이 남지 않아 확산 추이 분석이 불가능하다.
캘린더식 관행 방제발병 여부와 무관한 전면 살포로 약제비·노동력이 낭비되고, 동일 계열 약제 반복 사용으로 저항성이 유발된다.
환경센서 발병 예측 모델"발병 위험도"만 추정할 뿐, 실제 감염 개체와 위치를 특정할 수 없어 국소 방제로 연결되지 않는다.
실험실 정밀 진단 (PCR/ELISA)정확도는 높으나 시료 채취→결과 회신까지 1~3일이 걸리고 건당 비용이 발생해 상시 예찰 수단으로 부적합하다.
단순 영상 임계값 처리 (HSV)병반과 생리장해(질소 결핍, 광해, 자연 노화)의 색상 분포가 중첩되어 오탐이 다발한다. 조도 변화에 취약하다.
02 · WHY AI

규칙으로는 분리되지 않기 때문입니다

잿빛곰팡이 초기 병반과 저온 생리장해 반점은 RGB 색공간에서 분포가 겹칩니다. 임계값 규칙으로는 구분할 수 없고, 병해별로 써야 할 약제와 방제 방식이 다르기 때문에 "이상/정상" 이진 판정만으로는 자동 방제 명령을 만들 수 없습니다.

규칙 기반 분리 불가

병반의 색·형태는 품종, 생육 단계, 광량, 시비 상태에 따라 크게 변동합니다. 고정된 색 임계값으로는 생리장해와 병해를 나눌 수 없습니다.

다중 클래스 분류가 필수

살균제 계열, 환기 제어, 매개충 방제 등 병해별 대응이 다릅니다. 자동 제어 명령을 생성하려면 병해 종 단위 분류가 전제되어야 합니다.

비정형 촬영 환경

잎 겹침, 그림자, 이슬 반사, 잎 뒤집힘 등 변형 요인이 많아 사전에 정의할 수 없는 패턴을 학습으로 흡수해야 합니다.

결정 근거의 결합

이미지 신뢰도만으로는 오탐을 억제하기 어렵습니다. 최근 24시간 습도·결로 시간 등 환경 데이터를 결합해 확률을 보정합니다.

LeafGuard AI가 만드는 4가지 가치

VALUE 01
조기 발견

육안 대비 평균 3일 이상 빠른 병징 감지로 확산 초기에 차단합니다.

VALUE 02
국소 정밀 방제

감염 Zone 단위로만 방제해 약제 사용량을 30% 이상 줄입니다.

VALUE 03
표준화·기록화

진단 근거(이미지+Grad-CAM)와 방제 이력을 축적해 GAP 대장을 자동 생성합니다.

VALUE 04
무인화

야간·주말 포함 24시간 상시 예찰로 전담 인력 의존도를 제거합니다.

병해별 발병 조건(결로 지속시간, 엽온-기온 차) 산출용. SHT31은 고습 장기 안정성이 검증된 산업 표준품.

CONTROL
STM32G0 + RS-485 (Modbus RTU) · 릴레이 8ch

전기 노이즈·서지 환경에서 무선보다 유선이 안정적이며, Modbus RTU는 국내 복합환경제어기·전동밸브가 대부분 지원하는 사실상 표준.

EDGE AI
NVIDIA Jetson Orin Nano 8GB (대안: RPi 5 + Hailo-8L)

일 4,680장 원본 전송은 대역폭·비용상 비현실적. 온디바이스 추론으로 1.5초 지연과 네트워크 단절 시 자립 동작을 확보하고, TensorRT로 INT8 양자화.

AI MODEL
YOLOv8n → ONNX → TensorRT INT8 / EfficientNet-B0

소형 객체 검출 성능 대비 경량이라 Edge 실시간 처리에 적합하고 잎 인스턴스 분리로 발병엽률 계산 가능. 분류는 5.3M 파라미터로 세밀 텍스처에 강함.

TRAINING / MLOps
PyTorch 2.x · Albumentations · Grad-CAM
MLflow · DVC · Label Studio · GitHub Actions

계절·품종별 Data Drift로 재학습이 상시 발생하므로 데이터·모델 버전 관리가 필수. Grad-CAM은 사용자 신뢰 확보와 오탐 원인 분석에 사용.

BACKEND
Python 3.11 · FastAPI · Docker · AWS EC2 (서울)

비동기 처리로 다수 Edge 동시 수신 대응. AI 파이프라인과 언어 스택을 통일해 유지보수를 단순화하고, 국내 리전으로 지연·데이터 주권 확보.

NETWORK
PoE 이더넷 · LTE Cat.M1 백업 · MQTT over TLS 1.3

금속 골조·수분으로 Wi-Fi 감쇠가 심해 유선 우선. MQTT는 저대역폭·불안정 회선에서 QoS 1 기반 재전송을 보장.

DATABASE
PostgreSQL 16 + TimescaleDB · AWS S3

관계형 데이터와 고빈도 시계열을 단일 엔진에서 처리해 운영 복잡도를 낮추고, 이미지는 객체 스토리지로 분리(Glacier 수명주기).

FRONTEND / 알림
React 18 · TypeScript · Recharts · Grafana
FCM 푸시 · 카카오 알림톡 · SMS

웹 표준으로 PC·태블릿 반응형 대응, 설비 모니터링은 Grafana 재사용. 국내 농가 실사용 채널이 카카오톡에 집중되어 도달률이 가장 높고, 긴급은 SMS 이중 발송.

SECURITY
mTLS 디바이스 인증서 · JWT · AWS KMS

제어 명령이 위변조되면 오살포로 약해·안전사고가 발생할 수 있으므로 디바이스 단위 상호 인증이 필수.

07 · SCOPE

v1.0이 하는 일, 하지 않는 일

v1.0은 시설 토마토 단일 작물, 6개 병해 + 정상 = 7클래스로 한정합니다.

In Scope — v1.0 개발 범위

  1. 01실시간 잎 검출 및 병해 분류 — 2단계 파이프라인, 토마토 7클래스 온디바이스 추론
  2. 02발병엽률 산출 및 3단계 등급 판정 — 연속 프레임 검증, 환경 기반 신뢰도 보정
  3. 03방제 장치 자동 제어 — Modbus RTU Zone별 밸브·정량펌프, 살포 시간 자동 산출
  4. 04안전 인터록 모듈 — 재실 감지, 안전사용 간격 검증, 유량 피드백 자동 중단
  5. 05알림 시스템 — 등급별 푸시/알림톡/SMS, 승인 대기 및 재알림
  6. 06데이터 수집·저장 파이프라인 — S3 업로드, TimescaleDB 적재, 7일 Edge 버퍼링
  7. 07관리자 웹 대시보드 — 병해 현황 맵, 판정 이력, Grad-CAM 뷰어, 주간 리포트
  8. 08감사 로그 및 약제 사용 대장 — GAP 인증 양식 PDF 내보내기
  9. 09사용자 피드백 라벨링 — 정확/오탐 응답 수집 및 재학습 데이터셋 축적
  10. 10Edge 원격 관리 — OTA 모델 배포, 헬스체크, 원격 로그 수집
  11. 11설치 캘리브레이션 도구 — 화이트밸런스 보정, ROI 마스크 설정 UI

Out of Scope — 제외 및 사유

  • —음성 인식·명령 제어 온실 소음 환경에서 인식률 확보가 어렵고 오인식 오살포 리스크가 큼
  • —네이티브 모바일 앱 반응형 웹 + 알림톡 링크로 대체, v2.0 검토
  • —다국어 지원 한국어 단일. 수출형(영어·베트남어)은 별도 프로젝트
  • —온라인 학습 / 연합학습 월 1회 오프라인 배치 재학습. 실시간 학습은 품질 통제 불가
  • —세분화된 RBAC 관리자/작업자 2단계 고정. 조직 권한 체계는 v2.0
  • —토마토 외 작물 파프리카·오이·딸기는 데이터 확보 후 v1.5 순차 확장
  • —해충 검출 및 방제 별도 트랩 카메라·모델이 필요하므로 v2.0 분리
  • —수확량 예측 / 생육 진단 병해 감지 목적 외 기능
  • —약제 발주 자동화·결제 연동 사용량 기록까지만 제공
  • —노지 재배 지원 강우·강풍·직사광 대응은 별도 H/W 설계 필요
